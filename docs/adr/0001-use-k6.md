# 0001. Use Grafana k6 as the load testing tool

- Status: Accepted
- Date: 2026-10-18

## Context

The project needs a load testing tool whose scripts live in Git, can be reviewed like code, run in CI, and cost nothing to use locally. The tool must support HTTP, WebSocket, and gRPC, and produce results that can be compared over time.

## Decision

Use Grafana k6 (open source, AGPL-3.0).

## Consequences

- Test scripts are JavaScript files, versioned and reviewed like any other code.
- Thresholds are built in, so pass/fail criteria are part of the script.
- Official Docker image and GitHub Actions exist, which simplifies CI.
- Scripts run in k6's own JavaScript engine, not in Node.js. Runtime code cannot import npm packages (see ADR 0004).
- Browser-level testing is available through the bundled `k6/browser` module, which allows adding front-end scenarios later.
- We depend on k6's release cadence and must pin versions (see ADR 0003).

## Alternatives considered

| Tool | Reason not chosen |
|---|---|
| Apache JMeter | XML-based test plans are hard to review in Git, and the GUI-first workflow is heavier. |
| Gatling | Strong option, but scripts require Scala, Java, or Kotlin, which is a larger stack for this project. |
| Locust | Python-based. Good option, but we want the tool used in Grafana's own examples and its ecosystem. |
| Artillery | JavaScript and YAML. Viable, but k6's thresholds and Grafana integration are more mature for this goal. |
