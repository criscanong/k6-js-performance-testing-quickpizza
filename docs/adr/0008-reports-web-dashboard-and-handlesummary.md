# 0008. Generate reports with the web dashboard and `handleSummary`

- Status: Accepted
- Date: 2026-10-18

## Context

Results must be readable by people and comparable between runs, without paying for a hosted service. k6 offers several output options. Grafana Cloud is paid beyond its free tier and is excluded by ADR 0009.

## Decision

Use three outputs, all built into k6:

1. **Console summary** from `handleSummary()`, printed at the end of each run and suitable for CI logs.
2. **HTML dashboard**, generated by k6's built-in web dashboard. It is enabled with `K6_WEB_DASHBOARD=true` and exported to a file with `K6_WEB_DASHBOARD_EXPORT=<path>`. The dashboard is disabled by default.
3. **`summary.json`**, written by `handleSummary()`, for comparing runs across commits.

The community package `k6-reporter` was considered and is not used by default. It can be added in a later ADR if a specific layout is needed.

## Consequences

- No extra dependencies are required for reports.
- Reports must be enabled explicitly through environment variables. The Docker Compose and CI configuration must set them.
- Each run produces one HTML report. Names include environment, profile, and date so runs can be compared.
- Comparing runs over time relies on `summary.json`, which requires a small comparison script in a later phase.

## Alternatives considered

| Option | Reason not chosen |
|---|---|
| `k6-reporter` (community) | Works well, but adds a dependency on a third-party bundle loaded from a URL. |
| Grafana Cloud k6 | Paid beyond the free tier. Excluded by ADR 0009. |
| Grafana dashboards via Prometheus | Valuable, but planned as optional phase 7, after the core reports work. |
